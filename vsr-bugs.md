# Drawesome UI Bug List (vsr-bugs.md)
_Generated by scripts/ui-audit.mjs (npm run audit:ui) across phone / tablet / large-tablet (portrait+landscape) / desktop._
_Status: [ ] open · [~] in progress · [x] fixed & verified · [-] wontfix_

## High
- [x] **B1** (large-tablet-landscape 1366x1024) Large touch tablets get the desktop layout instead of the mobile experience
  - Root cause: The entire mobile/touch UI (chrome-free canvas, always-on quick bar, bottom-sheet tool rail, mobile actions/profile) is gated behind `@media (max-width: 1024px)` only. A landscape iPad-class tablet (1366px wide, `pointer: coarse`) exceeds 1024px, so all five mobile blocks miss and the desktop layout renders: `.mobile-quickbar` stays `display:none`, the tool rail shows as a fixed desktop side rail, and the top bar / multiplayer bar render. The owner wants large tablets to feel mobile. The audit reports `pointer: coarse` for every touch viewport and `fine` for desktop, so width alone is the wrong gate.
  - Fix: Extend the mobile-layout `@media (max-width:1024px)` blocks in src/App.css to ALSO trigger on `(pointer: coarse)` — i.e. change each `@media (max-width: 1024px)` to `@media (max-width: 1024px), (pointer: coarse)` — so real touch tablets get the mobile UI at any width without regressing 1366px laptops (which report `pointer: fine`). Apply to all five blocks at lines ~3535, ~3626, ~3706, ~3877, ~4267.
  - Files: src/App.css
  - → Fixed: Changed all five mobile-layout `@media (max-width: 1024px)` blocks (studio-shell/topbar/tool-rail bottom-sheet ~3535, chrome-free canvas + quickbar + mobile-actions ~3626, chat positioning ~3706, chat-room wrap ~3877, palette/swatch sizing ~4267) to `@media (max-width: 1024px), (pointer: coarse)`. A coarse-pointer 1366px device now hides `.topbar`/`.mp-bar` and shows `.mobile-quickbar`; desktop (fine pointer, >=1025px) is unchanged.
  - → Verified (round 1): large-tablet-landscape (1366x1024, coarse) now renders the mobile bottom-sheet tool rail (`aside.tool-rail.is-open` with `drawer-handle`) instead of the desktop side rail; the old `desktop-ux-missing`/desktop-tool-rail signature is gone. Desktop (1440x900, fine) still shows the desktop layout with 0 findings on all routes — no `desktop-ux-missing`, no horizontal-overflow. Resolved.
  - → Verified (round 2): fresh build + audit shows 0 findings across all 5 devices × 4 routes. No `mobile-ux-missing` on any touch tablet and no `desktop-ux-missing` on desktop (1440x900, non-touch). Stays resolved.

## Medium
- [x] **B2** (phone / tablet / large-tablet portrait+landscape) Marketing nav links are far below touch-target size
  - Root cause: `.marketing-nav a` (Discover / Paint Together / Pricing) renders ~21px tall on every touch viewport — below the 28px floor and well under the 44px guideline. The anchors have no padding or min-height; they are bare inline text links.
  - Fix: Give `.marketing-nav a` adequate hit area on touch: `min-height: 44px`, vertical padding, and `display: inline-flex; align-items: center;` (scoped to touch / small viewports so the desktop header stays compact). Style block is at src/App.css line ~996.
  - Files: src/App.css
  - → Fixed: Added a touch-scoped `@media (max-width: 1024px), (pointer: coarse)` rule for `.marketing-nav a` giving `display: inline-flex; align-items: center; min-height: 44px; padding: 4px 6px;` (src/App.css ~1001). Desktop header link styling is untouched.
  - → Verified (round 1): marketing route now shows 0 findings across all 5 devices (phone/tablet/large-tablet portrait+landscape/desktop). Resolved.
  - → Verified (round 2): marketing route still 0 findings on all 5 devices. Stays resolved.

- [x] **B3** (phone / tablet / large-tablet, all touch viewports) Canvas zoom controls and chat header/room icon buttons are under 44px
  - Root cause: A cluster of always-visible touch controls falls below the 44px (some below 40px) target: zoom controls `−` / `+` (38x38), `zoom-pct` (58x38), pan/hand `✋` (45x38); chat collapse `–` (37x42); and the chat room-info icon buttons `Invite` (61x32) and the `🌐` / `🔒` / `⚠️` `.mp-chat-iconbtn` (36x32). These share root causes by control group: the `.zoom-controls > button` sizing and the `.mp-chat-room` `.mp-chat-invite` / `.mp-chat-iconbtn` sizing.
  - Fix: Bump these controls to a 44px-min touch target under the mobile/touch layout — raise `.zoom-controls button` height to 44px, and raise `.mp-chat-room .mp-chat-invite` / `.mp-chat-iconbtn` min-height to 44px (with matching min-width for the icon buttons). Keep the desktop appearance unchanged. `.mp-chat-room` styles are at src/App.css ~3606; zoom-controls and `.mp-chat-iconbtn` are nearby in App.css.
  - Files: src/App.css
  - → Fixed: Added touch-scoped `@media (max-width: 1024px), (pointer: coarse)` rules: `.zoom-controls button` → 44px min-height/min-width (zoom-pct keeps 58px width); `.mp-chat-head button` → 44x44; `.mp-chat-room .mp-chat-invite` → 44px min-height; `.mp-chat-iconbtn` → 44x44. Desktop pills stay at their slim 38/32px sizes.
  - → Verified (round 1): the `studio` route (where zoom controls + chat header/room icon buttons live) now shows 0 findings on all touch viewports. Resolved.
  - → Verified (round 2): studio route still 0 findings on all touch viewports. Stays resolved.

No separate swatch rule needed.
  - → Verified (round 1): the prior 30x30 desktop-tool-rail swatch finding on large-tablet-landscape is gone; no `color-swatch` small-tap-target is flagged on any device. Resolved.
